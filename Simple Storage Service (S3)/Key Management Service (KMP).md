
## Personal Notes

  - Regional and Public Service.
  - Allows creation, storage, and management of keys.
  - Symmetric Keys and Asymmetric keys
  - Encryption and decryption operations.
  - Keys never leave KMS - Provides FIPS 140-2(L2)
  - KMS Keys: logical - ID, date, policy, desc & state. Backed by physical key material. 
  - Physical material can be generated by KMS or imported into KMS.
  - KMS keys can be used for up to 4KB of data. 
  - Different keys are used for key generation, encryption, and decryption. 
  - You'll also need permissions to do all of these actions as well. 
  - Data Encryption Keys (DEKs):
	  - generated using a KMS key, using the generate data key operation, creating a data cryption key that can encrypt and decrypt. KMS doesn't store the keys, it only provides the keys for each action to you in that moment,.
	  - GenerateDataKey works on items more than 4KB.
	  - Plaintext version: key that's in plain language to use soon after
	  - Ciphertext version: key that's encrypted for security. Can be given back to KMS for decryption
	  - generate key, use plaintext to create an encrypted version, use this to encrypt provided data, and then throw away the plaintext version of the data key. Store encrypted key with data. 
	  - You can use the original plaintext data key to ask KMS to decrypt the encrypted data key and then use that new key to decrypt any previously encrypted data. 
	  - KMS Keys are isolated to a region & never leave that region.
	  - Keys are either AWS Owned or Customer Owned . 
 - Customer owned:
	 - AWS Managed - created automatically by AWS when you use a service
	 - Customer Managed - created manually by the customer and are more configurable. 

  -  KMS Keys support rotation: the physical material that backs the keys changes once per year for security. 
  - Customer rotation is optional by default
  - KMS key contains backing key (and previous backing keys). As rotation occurs, older versions can still be decrypted. 

 - Key Policy (resource policy): each key has one. Key Policies + IAM Policies, allows a user to use the key to perform a single or more action such as encryption, decryption, and creation of keys.
